# 탐정학원 V3 실험실

V3(인디게임 경험과 게임플레이 확장)의 실험을 모아 둔 곳이다. **제품 코드(`src/`)와 확정된 화면(D안)은 건드리지 않는다.** 여기서 검수를 통과한 것만 제품으로 옮긴다.

- 브랜치: `feat/v3-indie-experience` (main 과 배포본은 그대로다)
- 보는 법: 개발 서버(`npm run dev`)를 켜고 <http://localhost:5183/lab/gate01/> (실험) · <http://localhost:5183/lab/gate02/> (메인 홈 비교) · <http://localhost:5183/lab/gate03/> (암호 풀이 화면 비교)
- 휴대폰에서: `npx vite --config lab/vite.lan.config.ts` 후 `http://<맥의 주소>:5184/lab/gate03/` (같은 와이파이)
- 의존성: `lab/package.json` 에만 있다(`cd lab && npm install`). 제품의 `package.json` 에는 넣지 않았다.

### 구조

```text
lab/gate01/shared/
  dot.ts        점 화면의 도구: 직접 찍는 그림(Sprite), 4×4 베이어 점묘
  corridor.ts   복도를 층으로 그린다: 바탕 밝기 · 전등마다의 빛 · 문에서 새는 빛 · 융단 · 먹선 · 표지 · 전경
  detective.ts  탐정 관절 모형: 크기·각도·동작을 값으로 받아 그 자리에서 찍는다
  game.ts       공간·물건·이동 지점(SPOTS)과 상태. 매 장면 "무엇을 어디에 그릴지"(FrameOut)만 내놓는다
  shell.ts      세 렌더러가 함께 쓰는 화면 틀과 측정값
lab/gate01/corridor-*.ts   FrameOut 을 그리는 쪽만 다르다 (Canvas 2D · PixiJS · Phaser)
lab/ink/                   Ink Studio 장면과 굽는 법
```

그리는 방식: **밝기 층**(회색)을 더하고 곱해 합친 뒤 4×4 베이어 격자로 흰 점·검은 점으로 바꾸고, 그 위에 **먹 층**(직접 찍은 그림)을 얹는다. 빛을 층으로 따로 두었기 때문에 전등이 꺼지거나 문이 열리면 점묘가 실제로 바뀐다.

공간은 데이터다. 물건과 이동 지점은 `game.ts` 의 `SPOTS` 에 있다(이름, 설 자리, 볼 쪽, 누르는 영역, 도착 동작, 한 줄 서술). 다른 공간을 만들 때는 이 표와 그림만 바꾼다.

비교용 주소 값: `?freeze=3`(그 시각에서 멈춤), `&spot=practice`(그곳에 도착한 상태로 시작). 멈춘 동안에는 어느 렌더러든 같은 장면을 그려야 한다.

### 측정 (2026-11-22)

같은 장면(240×160 점 화면, 걸어 다니는 동안)을 세 렌더러로 그렸다. 세 판은 정지 장면 네 곳에서 **화소 차이 0**, 두 색이 아닌 화소 0이다.

| | Canvas 2D | PixiJS 8.23 | Phaser 4.2 |
|---|---|---|---|
| 초당 장면 (보통 / CPU 4배 감속) | 60 / 58.5 | 60 / 59.5 | 60 / 60 |
| 한 장면에 든 시간 ms (보통 / 4배 감속) | 1.8 / 4.95 | 0.68 / 2.76 | 0.74 / 3.09 |
| 가장 오래 걸린 장면 ms (보통 / 4배 감속) | 7.4 / 26.2 | 2.4 / 8.2 | 1.9 / 13 |
| JS 용량 (gzip) | 21KB (9KB) | 562KB (165KB) | 1,360KB (356KB) |
| 첫 장면까지 (빌드본, 4배 감속) | 130~230ms | 390~450ms | 490ms |
| 첫 장면까지 (GPU 없는 환경) | 66~120ms | 약 1,400ms | 약 550ms |
| 쓰는 메모리 (JS 힙) | 3.6MB | 8.2MB | 9.8MB |
| 그리는 쪽 코드 | 70줄 | 224줄 | 221줄 |

- 잰 곳: 헤드리스 크로미움(390×700, 화면 배율 3, 개발 서버). 용량과 "첫 장면까지"는 각 페이지만 빌드해 잰 값이다.
- WebGL 두 판의 "한 장면에 든 시간"은 그리기 명령을 넘기기까지이고 GPU 가 칠하는 시간은 빠져 있다. Canvas 판은 칠하기까지 전부다. 같은 잣대가 아니다.
- 세 판 모두 CPU 4배 감속에서도 초당 58장면 이상이다.
- **실제 휴대폰에서는 재지 못했다.** 사파리 엔진(WebKit)에서는 세 판 모두 뜨고 두 색만 쓰는 것까지 확인했다.

### 채택과 제외

| 기술 | 판단 | 이유 |
|---|---|---|
| Canvas 2D + 층으로 나눈 밝기 + CPU 점묘 | **채택** | 지금 화면 크기에서 충분히 빠르고(4배 감속 5ms), 9KB 다. 제품의 그리는 방식(`mono-art.mjs`)을 그대로 실행 중으로 옮긴 것이라 화풍이 같다 |
| 코드 기반 관절 모형(`detective.ts`) | **채택** | 깊이에 따라 크기가 변하는 복도에서 어느 크기·각도로도 또렷하게 찍힌다. 그림 파일이 없다 |
| Ink Studio | **그림 굽는 도구로 채택** | 실행 의존성이 없고 명령줄로 여덟 방향 스프라이트 묶음과 법선 그림을 내보낸다. 돌려 보이는 물건(휘장·증거물)에 쓴다. 제품에는 구운 PNG 만 싣는다 |
| pixelart-gaussiansplat | **그림 굽는 도구로만 (보류)** | 금고·엠블럼이 잘 나왔지만 뷰어가 3.4MB(gzip 1.1MB)이고 GPU 가 없으면 초당 1장면이다. 두 색으로 제한하려면 장면 파일에서 두 군데를 우회해야 한다. 실행 중에는 쓰지 않는다 |
| PixiJS | **제외 (지금은)** | 화소 결과가 같고 4배 감속에서도 두 판 다 60장면에 가까운데, +156KB(gzip)와 느린 첫 장면을 치러야 한다. 전체 화면 셰이더 연출이나 큰 장면이 실제로 필요해지면 다시 본다 |
| Phaser | **제외** | +347KB(gzip). 공간이 세 곳이고 명령 단추가 DOM 이라 장면 관리·입력·카메라가 덜어 준 일이 없었다. 숨김·정리도 직접 처리해야 했다 |
| LibreSprite (GPL-2.0) | 필요할 때 | 사람이 직접 찍는 스프라이트용 편집기. 도구의 라이선스는 만든 그림에 미치지 않는다. 이번에는 쓰지 않았다 |
| Tiled, LDtk (MIT) | 제외 (지금은) | 공간이 한 화면짜리 세 곳이고 이동 지점이 네댓 개라 표(`SPOTS`)로 충분하다. 공간이 늘면 LDtk 를 다시 본다 |
| jsfxr (Apache-2.0, 2014년 이후 멈춤) | 보류 | 효과음은 Web Audio 로 직접 만드는 쪽을 먼저 본다(PART 5). 아직 실험하지 않았다 |

라이선스: Phaser·PixiJS·Ink Studio·pixelart-gaussiansplat·Spark·LDtk 는 MIT, jsfxr 는 Apache-2.0, LibreSprite 는 GPL-2.0(편집기). pixelart-gaussiansplat 저장소의 생물 모델(minotaur 등)은 MIT 가 아니어서 쓰지 않았다.

### 알아 둔 것 (다음 단계에 반영할 것)

- **밝기 층은 브라우저마다 조금 다르게 그려진다.** 실행 중에 캔버스로 굽기 때문에 크롬 엔진과 사파리 엔진의 점묘가 0.4%쯤 다르다(각자는 두 색만 쓴다). 어디서나 같은 점이어야 하면 제품의 배경처럼 빌드 때 PNG 로 구워야 한다.
- **그림자는 "미리 구운 그림을 곱하기"로 바꾸는 편이 낫다.** 지금은 반투명 타원이라 WebGL 판이 Canvas 와 화소를 맞추려고 우회 코드를 30~40줄 썼다.
- **층의 불투명도는 0 과 1 만 쓴다.** 중간값은 렌더러마다 한두 단계 어긋난다.
- 복도가 한 점 투시라 옆벽의 물건(게시판·문)이 얇게 보인다. 표지(작은 그림 간판)로 알아보게 했지만, 누르는 영역은 그림보다 넓게 잡았다. GATE 02 의 B안(넓은 복도)에서는 옆에서 본 구도를 따로 검토한다.
- 이동은 0.5~1.2초에 끝나게 했고 걷는 중에 누르면 건너뛴다. 걸음 수는 거리와 딱 맞지 않는다(발이 조금 미끄러진다).

### 두 안이 하는 일

**A안.** 탐정이 복도 앞쪽에 서 있다. 가까운 등이 11초마다 두 번 깜빡이고, 옆문이 17초마다 열렸다 닫히며, 끝 방의 사람이 23초 주기로 비켰다 돌아오고, 게시판의 종이가 13초마다 팔랑인다. 공고·연습실·승급 시험·신분증을 누르면 탐정이 그쪽으로 걸어가고(0.5~1.2초) 카메라가 그쪽으로 조금 밀린 뒤 화면이 바뀐다. 한 번 더 누르면 건너뛴다. 장면 자체는 누를 수 없다.

**B안.** 복도는 화면보다 넓다(340점, 화면에는 195점쯤 보인다). 왼쪽부터 기록 보관함 · 시험 게시판 · 연습실 문 · 승급 시험실 문 · 창.

- 물건을 누르면 탐정이 걸어가(0.45~0.9초) 그 앞에 서고, 서술 한 줄과 명령 창의 그 줄이 펼쳐진다. 같은 물건을 한 번 더 누르면 들어간다.
- 명령 창의 줄을 누르면 걸어가서 곧바로 들어간다(걷기 + 0.2초). 걷는 중에 한 번 더 누르면 건너뛴다.
- 들어서면 탐정이 오늘 할 일이 있는 곳으로 가 서 있다. 그래서 매일의 주 동선(오늘의 추리)은 걷지 않고 한 번 눌러 들어간다. 걷는 것은 다른 곳을 고를 때뿐이다.
- 탐정이 다른 곳에 가 있으면 오늘 할 일이 있는 물건에 모서리 괄호가 깜빡인다.
- 상태가 장면에 비친다: 오늘의 사건을 풀면 큰 시험지에 가위표, 승급 시험을 볼 수 있으면 시험실 유리에 불이 켜지고 19초마다 사람이 지나간다, 문 위 표찰은 다음 등급 글자, 연습실 앞에 서면 문이 열리며 빛이 쏟아진다, 벽시계는 실제 시각.
- 환경: 시험실 앞의 등이 13초마다 두 번 깜빡이고, 창밖 나뭇가지 그림자가 달빛 위에서 흔들린다.

| 홈이 뜨기까지 (보통 / 4배 감속) | 37 / 130ms | 84 / 316ms | 63 / 241ms |
| 누른 뒤 화면이 바뀌기까지 | 0.15초 | 0.5~1.2초 | 이미 그 앞이면 곧바로, 아니면 0.65~1.1초 |

- 스크립트 용량: 320KB → 359KB (gzip 98KB → 112KB). 두 안의 장면 코드가 함께 들어 있다. 하나를 고르면 줄어든다.
- 두 색: A안·B안 모두 검정·흰색이 아닌 화소가 화면 전체의 0.5% 미만(크로미움, 자동 테스트). 장면 캔버스 안은 0 (사파리 엔진에서 잰 값).
- 사파리 엔진(WebKit, Playwright): 두 안 모두 그려지고 걸어서 들어간다.
- 자동 테스트 20개(`e2e/home-variants.spec.ts`): 진입, 건너뛰기, 빠르게 여러 번 눌러도 한 번만 들어감, 모션 줄이기, 두 색, 375×667 · 390×664 · 375×812 · 430×932 배치.
- B안을 기본으로 올린 뒤: 기존 테스트 44개(입학부터 승급·신분증까지)가 B안 홈을 거쳐 통과한다. 줄의 테스트 이름은 예전 홈의 것을 물려받았다(`daily-file`, `practice-entry`, `exam-cta`, `identity`). 390×664 와 375×629(아이폰 13 미니의 사파리 화면 높이)에서 스크롤 없이 네 줄이 모두 보인다.

### 알아 둔 것

- 먹으로 검게 덮은 자리는 밑의 빛이 보이지 않는다. A안의 끝 방은 실험실 때부터 문 안의 불빛이 먹에 가려 사람이 윤곽선으로만 보였다. 문 안의 먹을 비워 고쳤다(실험실 판 `lab/gate01` 은 그대로다).
- B안에서 장면을 누르는 것과 줄을 누르는 것의 결과가 다르다(살펴보기 / 바로 들어가기). 화면 아래 안내 한 줄로 알렸지만, 낮은 화면에서는 자리가 없어 안내를 뺐다.
- 긴 화면(430×932)에서는 B안의 아래쪽이 빈다. 장면의 점 크기(2px)를 지키느라 장면을 키우지 않았다.
- A안은 낮은 화면(390×664)에서 장면 띠가 140px 쯤으로 얇아져 탐정이 무릎 아래까지만 보인다. 기존 배치를 유지한 결과다.

### 하지 못한 것

- 실제 휴대폰에서의 성능 측정과 사파리 앱 확인. 위 수치는 모두 맥의 헤드리스 브라우저다.
- 효과음(발걸음, 문). 걷기에 맞춘 소리는 아직 없다.
- 도착 뒤의 클로즈업 연출(시험지가 커지며 책상으로 이어지는 장면, 봉투 등장). 지금은 명령 창의 줄이 펼쳐지고 기존의 격자 전환으로 넘어간다.

## GATE 03 · 퍼즐 UX 비교 (암호 풀이)

지금의 풀이 화면은 제목·긴 설명·시도 기록·숫자 메모·자물쇠·힌트·제출이 한 화면에 몰려 있다. 같은 암호 문제(오늘의 추리 · 자료실 금고의 암호)를 세 가지 다른 구성으로 실제로 풀 수 있게 만들었다. **지금의 풀이 화면은 바꾸지 않았다**(부품을 나눈 뒤에도 화소 단위로 같음을 확인했다). 사용자가 플레이해 보고 고른다.

| | 주소 | 내용 |
|---|---|---|
| 나란히 보기 | `/lab/gate03/` | 네 화면을 같은 문제·같은 크기로. 휴대폰에서는 각 안을 전체 화면으로 여는 단추가 나온다. |

### 세 안이 하는 일

**A안 · 접기·펼치기.** 패널 세 칸(사건 · 시도 기록 · 숫자 메모)을 머리줄로 접고 편다. 처음에는 시도 기록만 펴져 있다. 접힌 패널에는 안에 든 것이 남는다: 사건은 "1~9 가운데 서로 다른 숫자 3개", 시도 기록은 글 없이 숫자와 표시만 놓은 간편 보기(제외한 숫자는 점선 칸에 줄, 후보는 뒤집힌 칸), 메모는 "제외 5 7 9 · 후보 6". 자물쇠와 제출 단추는 아래에 고정이고, 패널을 접은 만큼 드럼의 창이 길어진다(114~214px). 패널이 화면보다 길어지면 패널 쪽만 스크롤된다.

**B안 · 장면 전개.** 문제가 자료실의 장면으로 펼쳐진다: 문으로 들어선다 → 책상의 기록을 살핀다(시도 기록·숫자 메모·받은 수사 지원) → 금고 앞에서 드럼을 돌린다 → 금고가 열린다(안의 장부가 보인다) → 결과. 책상과 금고 사이는 장면의 물건이나 아래 단추("금고 앞으로" / "기록 보기")로 오간다. 누른 즉시 화면이 바뀌고 탐정은 0.4~0.7초 걸어 뒤따른다. 책상에서 적은 메모는 금고 앞에서도 한 줄로 보인다. 기록과 자물쇠를 한 화면에서 같이 볼 수는 없다.

**C안 · 혼합형.** 처음 여는 사건은 도입 장면으로 시작한다(자료실, 세 문장, 다 찍히면 스스로 걷히고 누르면 바로 걷힌다). 그 뒤는 자물쇠가 화면의 주인이고, 조건은 수사 수첩에 담겨 있다. 표지를 누르면 접히고(표지에 "기록 5 · 중요 1 · 메모 3 · 지원 1"이 남는다), 간편 보기는 기록의 숫자와 표시만, 전체 보기는 사건·시도 기록·숫자 메모·받은 수사 지원을 한 장에 보여 준다. 기록에 '중요' 표시를 하면 간편 보기에 그것부터 글과 함께 나온다. 수첩을 펴고 접어도 자물쇠의 숫자는 그대로다.

세 안 모두: 판정·힌트·보상·시간 기록은 기존 엔진 그대로다. 접고 편 상태, 수첩 상태, 중요 표시, B안에서 선 곳은 새로고침해도 남는다. 나갔다 와도 돌리던 숫자와 메모가 그대로다.
