# 탐정학원 V3 실험실

V3(인디게임 경험과 게임플레이 확장)의 실험을 모아 둔 곳이다. **제품 코드(`src/`)와 확정된 화면(D안)은 건드리지 않는다.** 여기서 검수를 통과한 것만 제품으로 옮긴다.

- 브랜치: `feat/v3-indie-experience` (main 과 배포본은 그대로다)
- 보는 법: 개발 서버(`npm run dev`)를 켜고 <http://localhost:5183/lab/gate01/>
- 휴대폰에서: `npx vite --config lab/vite.lan.config.ts` 후 `http://<맥의 주소>:5184/lab/gate01/` (같은 와이파이)
- 의존성: `lab/package.json` 에만 있다(`cd lab && npm install`). 제품의 `package.json` 에는 넣지 않았다.

## GATE 01 · 오픈소스와 아트 실험

| 데모 | 주소 | 내용 |
|---|---|---|
| 복도 이동 (Canvas 2D) | `gate01/corridor-canvas.html` | 층으로 나눈 복도, 탐정의 이동, 환경의 변화. 엔진 없음 |

### 구조

```text
lab/gate01/shared/
  dot.ts        점 화면의 도구: 직접 찍는 그림(Sprite), 4×4 베이어 점묘
  corridor.ts   복도를 층으로 그린다: 바탕 밝기 · 전등마다의 빛 · 문에서 새는 빛 · 융단 · 먹선 · 표지 · 전경
  detective.ts  탐정 관절 모형: 크기·각도·동작을 값으로 받아 그 자리에서 찍는다
  game.ts       공간·물건·이동 지점(SPOTS)과 상태. 매 장면 "무엇을 어디에 그릴지"(FrameOut)만 내놓는다
  shell.ts      세 렌더러가 함께 쓰는 화면 틀과 측정값
lab/gate01/corridor-*.ts   FrameOut 을 그리는 쪽만 다르다 (Canvas 2D · PixiJS · Phaser)
lab/ink/                   Ink Studio 장면과 굽는 법
```

그리는 방식: **밝기 층**(회색)을 더하고 곱해 합친 뒤 4×4 베이어 격자로 흰 점·검은 점으로 바꾸고, 그 위에 **먹 층**(직접 찍은 그림)을 얹는다. 빛을 층으로 따로 두었기 때문에 전등이 꺼지거나 문이 열리면 점묘가 실제로 바뀐다.

공간은 데이터다. 물건과 이동 지점은 `game.ts` 의 `SPOTS` 에 있다(이름, 설 자리, 볼 쪽, 누르는 영역, 도착 동작, 한 줄 서술). 다른 공간을 만들 때는 이 표와 그림만 바꾼다.

비교용 주소 값: `?freeze=3`(그 시각에서 멈춤), `&spot=practice`(그곳에 도착한 상태로 시작). 멈춘 동안에는 어느 렌더러든 같은 장면을 그려야 한다.

### 측정 (2026-11-22)

같은 장면(240×160 점 화면, 걸어 다니는 동안)을 세 렌더러로 그렸다. 세 판은 정지 장면 네 곳에서 **화소 차이 0**, 두 색이 아닌 화소 0이다.

| | Canvas 2D | PixiJS 8.23 | Phaser 4.2 |
|---|---|---|---|
| 초당 장면 (보통 / CPU 4배 감속) | 60 / 58.5 | 60 / 59.5 | 60 / 60 |
| 한 장면에 든 시간 ms (보통 / 4배 감속) | 1.8 / 4.95 | 0.68 / 2.76 | 0.74 / 3.09 |
| 가장 오래 걸린 장면 ms (보통 / 4배 감속) | 7.4 / 26.2 | 2.4 / 8.2 | 1.9 / 13 |
| JS 용량 (gzip) | 21KB (9KB) | 562KB (165KB) | 1,360KB (356KB) |
| 첫 장면까지 (빌드본, 4배 감속) | 130~230ms | 390~450ms | 490ms |
| 첫 장면까지 (GPU 없는 환경) | 66~120ms | 약 1,400ms | 약 550ms |
| 쓰는 메모리 (JS 힙) | 3.6MB | 8.2MB | 9.8MB |
| 그리는 쪽 코드 | 70줄 | 224줄 | 221줄 |

- 잰 곳: 헤드리스 크로미움(390×700, 화면 배율 3, 개발 서버). 용량과 "첫 장면까지"는 각 페이지만 빌드해 잰 값이다.
- WebGL 두 판의 "한 장면에 든 시간"은 그리기 명령을 넘기기까지이고 GPU 가 칠하는 시간은 빠져 있다. Canvas 판은 칠하기까지 전부다. 같은 잣대가 아니다.
- 세 판 모두 CPU 4배 감속에서도 초당 58장면 이상이다.
- **실제 휴대폰에서는 재지 못했다.** 사파리 엔진(WebKit)에서는 세 판 모두 뜨고 두 색만 쓰는 것까지 확인했다.

### 채택과 제외

| 기술 | 판단 | 이유 |
|---|---|---|
| Canvas 2D + 층으로 나눈 밝기 + CPU 점묘 | **채택** | 지금 화면 크기에서 충분히 빠르고(4배 감속 5ms), 9KB 다. 제품의 그리는 방식(`mono-art.mjs`)을 그대로 실행 중으로 옮긴 것이라 화풍이 같다 |
| 코드 기반 관절 모형(`detective.ts`) | **채택** | 깊이에 따라 크기가 변하는 복도에서 어느 크기·각도로도 또렷하게 찍힌다. 그림 파일이 없다 |
| Ink Studio | **그림 굽는 도구로 채택** | 실행 의존성이 없고 명령줄로 여덟 방향 스프라이트 묶음과 법선 그림을 내보낸다. 돌려 보이는 물건(휘장·증거물)에 쓴다. 제품에는 구운 PNG 만 싣는다 |
| pixelart-gaussiansplat | **그림 굽는 도구로만 (보류)** | 금고·엠블럼이 잘 나왔지만 뷰어가 3.4MB(gzip 1.1MB)이고 GPU 가 없으면 초당 1장면이다. 두 색으로 제한하려면 장면 파일에서 두 군데를 우회해야 한다. 실행 중에는 쓰지 않는다 |
| PixiJS | **제외 (지금은)** | 화소 결과가 같고 4배 감속에서도 두 판 다 60장면에 가까운데, +156KB(gzip)와 느린 첫 장면을 치러야 한다. 전체 화면 셰이더 연출이나 큰 장면이 실제로 필요해지면 다시 본다 |
| Phaser | **제외** | +347KB(gzip). 공간이 세 곳이고 명령 단추가 DOM 이라 장면 관리·입력·카메라가 덜어 준 일이 없었다. 숨김·정리도 직접 처리해야 했다 |
| LibreSprite (GPL-2.0) | 필요할 때 | 사람이 직접 찍는 스프라이트용 편집기. 도구의 라이선스는 만든 그림에 미치지 않는다. 이번에는 쓰지 않았다 |
| Tiled, LDtk (MIT) | 제외 (지금은) | 공간이 한 화면짜리 세 곳이고 이동 지점이 네댓 개라 표(`SPOTS`)로 충분하다. 공간이 늘면 LDtk 를 다시 본다 |
| jsfxr (Apache-2.0, 2014년 이후 멈춤) | 보류 | 효과음은 Web Audio 로 직접 만드는 쪽을 먼저 본다(PART 5). 아직 실험하지 않았다 |

라이선스: Phaser·PixiJS·Ink Studio·pixelart-gaussiansplat·Spark·LDtk 는 MIT, jsfxr 는 Apache-2.0, LibreSprite 는 GPL-2.0(편집기). pixelart-gaussiansplat 저장소의 생물 모델(minotaur 등)은 MIT 가 아니어서 쓰지 않았다.

### 캐릭터 제작 방식 비교

| 방식 | 결과 | 판단 |
|---|---|---|
| ① 직접 찍은 2D 스프라이트 (문자 격자 16×28) | 서기 2장면, 걷기 4장면 | 손맛은 좋지만 크기·각도마다 다시 찍어야 한다. 내가 찍은 것은 견본 수준이다 |
| ② 코드 기반 관절 모형 | 16방향, 걷기 12장면, 짚기·살피기·모자 인사·앉기, 키 14~80점 | **채택.** 실루엣이 가장 또렷하고 복도의 깊이 이동에 맞는다 |
| ③ 입체 모형을 구운 스프라이트 (Ink Studio) | 여덟 방향 × 걷기 12장면, 점묘 음영 | 부피감이 장점. 지금 모형은 코트가 둥글어 실루엣이 무디다. 물건에 더 어울린다 |

칸 크기는 32×48(키 44점)과 48×64(키 60점)를 견줬다. 44점에서도 모자·코트·다리가 읽힌다. 눈은 50점부터, 모자 띠는 30점부터 찍는다.

### 알아 둔 것 (다음 단계에 반영할 것)

- **밝기 층은 브라우저마다 조금 다르게 그려진다.** 실행 중에 캔버스로 굽기 때문에 크롬 엔진과 사파리 엔진의 점묘가 0.4%쯤 다르다(각자는 두 색만 쓴다). 어디서나 같은 점이어야 하면 제품의 배경처럼 빌드 때 PNG 로 구워야 한다.
- **그림자는 "미리 구운 그림을 곱하기"로 바꾸는 편이 낫다.** 지금은 반투명 타원이라 WebGL 판이 Canvas 와 화소를 맞추려고 우회 코드를 30~40줄 썼다.
- **층의 불투명도는 0 과 1 만 쓴다.** 중간값은 렌더러마다 한두 단계 어긋난다.
- 복도가 한 점 투시라 옆벽의 물건(게시판·문)이 얇게 보인다. 표지(작은 그림 간판)로 알아보게 했지만, 누르는 영역은 그림보다 넓게 잡았다. GATE 02 의 B안(넓은 복도)에서는 옆에서 본 구도를 따로 검토한다.
- 이동은 0.5~1.2초에 끝나게 했고 걷는 중에 누르면 건너뛴다. 걸음 수는 거리와 딱 맞지 않는다(발이 조금 미끄러진다).
